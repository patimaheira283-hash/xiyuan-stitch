# 冻结与发布流程

1. 唯一版本定义在 `xiyuan_mvp/__init__.py`；修改版本时同步当前 README、使用说明和变更记录。
2. 执行 `Setup.ps1 -Test -Neural`，运行全套测试。新增测试依赖写入 `requirements/windows-test.txt`。
3. 使用 `requirements/windows-release.lock.txt` 复现发布构建环境。模型按 `docs/delivery/model-checksums.json` 校验；将 LoFTR 和 RAFT Large 放入 `TORCH_HOME/hub/checkpoints`。
4. 用 `python -m scripts.build_desktop --neural --clean --output .work/release-0.5.1` 构建。将根目录 `examples/` 及 `docs/delivery/` 拷入 `XiyuanAI`，执行当前包的四案例离线验收。
5. 提交全部源码变更后，执行 `python -m scripts.package_delivery --output deliverables/0.5.1/xiyuan-source-0.5.1.zip`。该命令只从 Git HEAD 打包，拒绝未提交的受跟踪改动，写入提交和逐文件清单。
6. 从该源码包解压后的目录构建 wheel：`python -m pip wheel . --no-deps --no-build-isolation --wheel-dir <发布目录>`；在独立虚拟环境与仓库外目录安装并验通 CLI。
7. 核对 wheel 内所有 `xiyuan_mvp/` 文件与源码 ZIP 一致，桌面验收 `version` 与发布版本一致，确认四条记录通过。
8. 生成 Release 清单和 SHA256；建立对应 Git 标签，推送到私有 GitHub 仓库，附上交付包与验证记录。不得覆盖旧发布资产。

GitHub Actions 负责干净检出后的 CPU 测试和 wheel 独立安装。它不下载模型，不代替本地真实模型验收，不代表真人盲评。
