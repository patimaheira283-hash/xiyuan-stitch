# GPT 直接融合首轮测试

日期：2026-09-09。数据、请求和原始结果均已保存在项目中。

## 结论

**使用现有 CC Switch 的 Codex 配置，可以通过 Responses 图像工具直接融合两张图片。** 本次完成 3 组实际生成，全部返回图片，耗时 46.7–68.8 秒。这里只表示通道和这三次请求成功，不等于拼接质量全部达标。

文字校验板保留了 4 行 × 6 列的格子、对应行列编号和 101–406 的数字，标题和页脚目视正确。咖啡照片保留了一个杯子、一个碟子和一把勺子的整体构图，但杯沿、反光、木纹等局部细节与参考图存在差异。砖墙返回了一张连续纹理图，但长宽比与请求、参考图明显不同，砖缝对应位置也有偏移。

**不能把这批结果称为“已验证的 GPT Image 2.5 high 档性能”。** 请求指定了 `gpt-image-2.5-sunburst`、`high`、`1536x1024`；服务商返回的图像工具没有声明图像模型名称，质量回报分别为 low、low、medium，砖墙尺寸也被改写。原因尚未查明，可能发生在中转或工具执行阶段，不能据此断言一定由哪一层导致。

## 实际配置与排查

- 凭据：CC Switch 当前 Codex Provider「Next Stop」，仅在本机后端读取。
- `gpt-5.5` 纯文本 Responses 请求：HTTP 200，正常完成。
- `gpt-5.5` 携带两张图片的看图请求：HTTP 404，`subscription_api_error / upstream_rejected / OpenAI returned HTTP 404`。
- `gpt-5.5` 携带图片与图像工具的融合请求：同样 HTTP 404。
- `gpt-6-astra` 携带同一组图片：HTTP 200，正确描述咖啡杯、碟子、勺子和木桌。
- `gpt-6-astra` 调用图像工具：三组均完成。

没有切换到其他 Provider，没有改写 CC Switch 或 Codex 的全局配置。最初另测了 `/images/edits` 通道，helper 返回失败；该结果不用于评价 Codex Responses 的能力。

## 如何读这些指标

SSIM 和 MAE 在把生成图缩放到参考图大小后计算，没有额外做几何对齐或颜色校正。因此结果同时反映纹理变化、构图漂移、颜色变化和重采样差异。SSIM 0.856 不代表“85.6% 的拼接成功率”。不同内容的 SSIM 也不宜直接当作任务难度排名。

砖墙的输出长宽比相对于参考图变化约 22.1%，这会影响缩放比较结果。图像依然可能看起来连贯，但不能据此称为保持原图几何结构的拼接。

界面的滑动对照把两图统一显示在参考图画布上；比例不同时显示会拉伸。点击“生成结果”或下载可以查看原始比例。

## 素材与测试边界

素材库已整理 5 个来源、10 组样例。照片均从 scikit-image 本机包中选择，并保留许可与来源：砖墙和草地为 CC0；咖啡照片为 Rachel Michetti 的 CC0 图像；火箭照片为 SpaceX 公共领域图像；文字板由本项目程序绘制。

这次实际调用了其中 3 组，每组生成 1 次。样例是从一张完整图中裁出两张有重叠的视野；没有模拟真实相机位移、大视差、运动物体。完整参考图没有提交给模型。

没有测试所有 10 组、随机重复稳定性或与申请书本地管线的公平对比。由于返回参数不一致，后续应先确认通道是否能严格执行所选图像模型、质量和尺寸，再扩大样本量。
